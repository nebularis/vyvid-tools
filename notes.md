# Note register

**Unit type:** Register

A note says how to do something with a tool. Each one was measured or run, and its Evidence cell says what was run and on which version. A note holds for the versions it names and for the platform it was run on, until it is run again. A project may keep a register of the same type and name one of these rows in its Specialises column.

| ID | Tool | Claim | Problem shape | Evidence | Activity | Technology | Specialises | Overrides |
|---|---|---|---|---|---|---|---|---|
| NOTE-1 | mise | **`mise exec -- <program>` replaces the mise process with the program, so no mise process is left as a parent that could leave a child behind.** | A program started through mise exec is stopped and a stray child process remains. | Ran `mise exec -- sleep 311` in the background of a shell and read `ps` for the pid the shell reported. That pid was `sleep 311` itself and had no children. mise 2026.9.12, macOS arm64. Not run on Linux. | | | | |
| NOTE-2 | mise | **SIGKILL to `mise run <task>` leaves its task running, since SIGKILL cannot be caught. SIGINT or SIGTERM to the mise pid stops the task.** | A time limit or a kill -9 on mise run leaves the task's program running after mise is gone. | A Python driver started `mise run` for a task that runs one `sleep` and signalled the mise pid itself, not a shell around it, with MISE_TRUSTED_CONFIG_PATHS scoped to a scratch folder. SIGKILL: mise exited -9 and the sleep survived with parent pid 1. SIGTERM: mise reported the task killed by SIGTERM, exited 1, and the sleep was gone. SIGINT: mise exited 130 and the sleep was gone. mise 2026.9.12, macOS arm64. | | | | |
| NOTE-3 | mise | **As the leader of its own session, `mise run` keeps its task in its own process group, so signalling the group stops the task. Otherwise the task has a process group of its own.** | A group kill of a mise run reaches the task in one setup and misses it in another. | A Python driver started `mise run` with `start_new_session=True` and read pid, ppid and pgid with `ps`. The task's pgid equalled mise's pid, and `os.killpg` with SIGKILL removed both, while SIGKILL to the mise pid alone left the sleep running with parent pid 1. Started without `start_new_session`, mise kept the driver's pgid and the task's pgid was its own pid. mise 2026.9.12, macOS arm64. | | | | |
| NOTE-4 | mise | **`mise <task>` runs a task without `run` when no mise command has that name. `mise run <task>` runs it whatever its name.** | Whether a task needs the run word, and what happens when a task is named like a mise command. | A scratch mise.toml with tasks `hello` and `ls`. `mise hello` and `mise run hello` both printed the task's output. `mise ls` listed the installed tools, and `mise run ls` ran the task. mise 2026.9.12, macOS arm64. | | | | |
| NOTE-5 | uv | **`uv tool install --editable <folder>` installs a tool that runs the folder's current source, so a later edit shows with no reinstall.** | A tool installed from a working tree runs old code after the code changed. | A scratch package with one script entry point and the hatchling backend, with UV_TOOL_DIR and UV_TOOL_BIN_DIR in a scratch folder. After the editable install the tool printed its first message. After the module body was edited, with no reinstall, it printed the new one. After `uv tool install --force` without `--editable` a further edit was not seen. A changed entry point or dependency was not tried. uv 0.13.4, macOS arm64. | | | | |
| NOTE-6 | cabal | **`cabal build --offline` needs no network where the dependencies are already in the store, and stops with error Cabal-7125 for a package that is not.** | A build is run with no network and it is unclear whether it can succeed. | CABAL_DIR was a copy of an existing cabal directory, with its package index and store, in a scratch folder. A one-executable project depending on `HUnit ==1.6.2.0`, which the store holds, configured, compiled and linked. With the dependency changed to `acme-missiles`, which the store lacks, it exited 1 with "--offline was specified, hence refusing to download the package: acme-missiles version 0.3." The network was not cut, so the first build shows the flag was honoured and no more. cabal-install 3.16.1.0, ghc 9.10.3, macOS arm64. | | | | |
| NOTE-7 | ghc | **`ghc -fwrite-ide-info -hiedir=<dir>` writes one `.hie` file per module into `<dir>`. Without `-fwrite-ide-info` no `.hie` file is written.** | Getting the .hie files of a program for tools that read symbols and types. | A one-module program. `ghc -c -fwrite-ide-info -hiedir=hie -odir=out -hidir=out Hello.hs` produced `hie/Hello.hie`. Without `-fwrite-ide-info` there was none, and without `-hiedir` it was written beside the source. `-fno-code` with both flags wrote it too. A `-outputdir out` given after `-hiedir=hie` moved the file into `out`. ghc 9.10.3, macOS arm64. | | | | |
| NOTE-8 | ghc | **A Template Haskell splice runs when ghc compiles the module that uses it, not when the program runs.** | Code in a splice, such as a file write, happens at an unexpected time or place. | A module whose splice used `runIO` to write a marker file into the working directory, and a main module that used the splice. `ghc -odir out -hidir out -o prog Main.hs` created the marker. After deleting it, `./prog` printed the splice's value and did not create it again. ghc 9.10.3, macOS arm64. | | | | |
| NOTE-9 | mise | **A `mise` shim picks the tool's version from the working folder, so out of the project it fails, and in the project under a scratch `HOME` it starts installing the tool into that `HOME`.** | Running a tool from a scratch environment so that a real home folder is not touched. | With `HOME` set to an empty folder, `uv --version` through the shim, run from a folder outside the project, printed "uv is not a valid shim". With the real `HOME` outside the project it printed "No version is set for shim: uv". With the scratch `HOME` inside the project it printed that mise was installing 1 tool. Calling the installed binary by its full path with `UV_CACHE_DIR` in the scratch folder avoided all three. mise 2026.9.12, macOS arm64. |  |  |  |  |
| NOTE-10 | python | **Read text with an explicit encoding, as `Path.read_text(encoding="utf-8")`. A bare read on Windows decodes with the console codepage and raises `UnicodeDecodeError` on a valid UTF-8 character outside it.** | A check that passes on macOS and Linux and fails on every Windows checkout on reading a tracked file. | A check that read a tracked data file with a bare `Path.read_text()` raised `UnicodeDecodeError` on every Windows checkout, deterministically, and passed on macOS and Linux, until the read named its encoding. The Python and Windows versions were not recorded when it was found, so this holds as found and is to be run again. | | | | |
